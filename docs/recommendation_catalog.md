# Recommendation catalog callable

`get_recommendation_catalog` requires Firebase authentication. It returns `recommendations`, an array of distinct unseen products in the signed-in user's preferred category and categories represented by their saved products. Candidates come from users with valid demographics, ordered within each category by similarity score, age difference, user ID, and bought-before-saved products. The catalog interleaves categories, starting with the profile preference. The response includes `sourceProductId`, product details, category ID, and a reason. It creates **no** `productEvents` record: fetching the catalog does not imply every row was seen.

When a person opens a catalog row, Flutter calls the existing `get_recommendation` callable with `{ "sourceProductId": "..." }`. The backend rechecks current eligibility, creates one `recommendation_shown` event, and returns the usual `recommendation` object with `recommendationEventId`. That event can be used by `save_recommended_product`. The original parameterless top-pick call remains available and selects the first eligible catalog candidate. If no peer has an unseen product in a saved category, that category has no row.

This implementation gathers every eligible row in one response. It fits the current small project dataset; a larger collection needs pagination and an explicit response-size policy. The Flutter catalog can use a short-lived in-memory copy but cannot display it after an app restart. `get_recommendation_catalog` and the updated `get_recommendation` were deployed to `whynot-f4ae6` on October 26, 2026. Firebase lists both as active, and an unauthenticated catalog call returns 401 `UNAUTHENTICATED`; a signed-in device run remains to be checked.
